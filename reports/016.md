## Worker summary

I added the per-project Git panel (status, Refresh, Merge, Pull, Push). `python -m pytest tests` passes: 87 tests, including the new `tests/test_git_panel.py`. I did not commit, so there is no commit hash. The orchestrator commits.

**What changed**
- **`agentdesk/core.py`**
  - New helpers: `git_remote`, `git_status`, `git_fetch`, `git_merge`, `git_pull` and `git_push`.
  - Status covers branch, base, clean or dirty, ahead/behind the upstream, and `auto/*` branches with commits ahead of base.
  - Merge requires the repo to be on the base branch with a clean tree. On a conflict it runs `merge --abort` and returns the conflicting files.
  - Pull is `--ff-only`. Push never forces and only accepts the current or base branch.
- **`agentdesk/server.py`**
  - `GET /api/p/<slug>/git` returns the status.
  - `POST /api/p/<slug>/git/{fetch,merge,pull,push}` runs an action. I used the existing `/api/p/` route style rather than `/api/projects/`.
  - Any action is refused while a run is going for that project.
  - Merge, pull and push need `confirm: true` in the request.
- **`agentdesk/web/index.html`**
  - A new Git section shows the status, the `auto/*` list with commit counts, a branch picker, and the Refresh, Merge, Pull and Push buttons.
  - Merge, Pull and Push each ask for confirmation first, showing branches, commit count and remote URL.
  - Pull and Push are disabled with the hint "local-only project" when there is no remote.
  - Git's own message is shown below the buttons.
- **`tests/test_git_panel.py`**: uses a local bare repo as the remote and covers:
  - local-only projects
  - status
  - push, pull and fetch, including a diverged pull being refused and a non-fast-forward push being rejected
  - a clean merge, and a conflicting merge that leaves HEAD and the working tree unchanged and names the conflicting file
  - merge refused on a dirty tree or when not on the base branch
  - the HTTP route driven with `urllib`, including the confirm requirement and the refusal while a run is going

**Not verified:** the HTML panel was never loaded in a browser, so the UI wiring and the `confirm()` dialogs are untested. The "run in progress" refusal is only tested with `Runner.running` mocked.

NOTES:
- Git panel helpers are `core.git_*`. Mutating routes need `confirm: true` and are refused while `runner(p).running()`.
- Merge only works from a clean base-branch checkout, and pull and push use the first remote (origin preferred).
- The `git` panel loads once per project switch and after its own actions, not on the poll.

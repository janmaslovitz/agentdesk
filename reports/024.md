**What the window does now**
- **Repository:** shows `origin`. You can paste an https URL, `git@host:owner/name`, or `owner/name`, or press **List** to pick from `gh repo list`. **Connect…** asks first, then sets or adds `origin`; git's errors are shown as they are. Input with a leading `-`, spaces or shell characters is rejected, as are passwords in URLs, local paths, `file://` and `ext::`.
- **GitHub account:** a dropdown of gh's accounts, with ★ on the active one. **Use for this project** saves it in project.toml as `[git] account = "…"`. That key is left out of exports because it belongs to this computer. **Make active in gh** runs `gh auth switch`.
- **Running as the account:** fetch, pull, push and the PR calls run as the saved account. The token from `gh auth token -u` goes only into that one command's environment, never on a command line, in a file, a log or a reply, and outputs are scrubbed for tokens. Each result says which account it used. ssh and local remotes keep using git's own credentials.
- **Push:** you can push the current branch or the base branch; the confirm says when it will set the upstream.
- **Pull requests:** lists open PRs, shows a PR's checks when you click **Checks**, opens a PR in the browser, and creates one (title, description, draft). Creating asks first and needs the branch pushed. There is no merge.
- **No gh or not logged in:** the window says what's wrong and which command to run, and fetch/merge/pull/push still work. gh answers are reused for 5 seconds; **Refresh** fetches and asks gh again.
- **Server:** the existing routes are unchanged. New ones: GET `/api/p/<slug>/git/{gh,repos,prs,checks}` and POST `/api/p/<slug>/git/{remote,account,switch,pr,open}`; everything except `open` needs `confirm: true`. The server already handles each request in its own thread, and every call has a timeout and opens no window.
- README has a new "The Git window" section and CHANGELOG has entries under Unreleased. All edited files keep CRLF.

## Brief

Goal: add a third chat mode, "planner", beside assistant and coworker. Full spec is task 006 (tasks/006-chat-planner-mode.md in data/projects/agentdesk). Summary: the user describes work; the planner (read-only tools Read/Glob/Grep plus propose_plan, update_plan, cancel_plan) writes a plan of ordered tasks (goal, files, tier, depends) as draft task files. The chat shows a plan card with Approve and start / Edit / Cancel, reusing the approval card from task 003. Approve turns drafts into real tasks and starts the queue as "Run all", and the chat reports progress and blocked tasks. A Stop button uses stop_run without approval. The planner never edits repo code, never pushes, and reports blocked tasks without rewriting the plan.

## Worker summary

The check now passes: `python -m pytest -q -x` gives 80 passed, and the planner tests passed on three repeat runs.

**Cause:** this was a real Windows bug, not a flaky test. Saving `state.json` writes a temp file and renames it over the old one. Windows refuses that rename while any other handle has `state.json` open. That happens more now because the plan watcher reads `state.json` every 2 seconds while a run is writing it, which in the real app could crash a run mid-save.

**Fix (in `agentdesk/core.py`):**
- New helper `replace_file`: if the rename hits `PermissionError`, it retries up to 40 times, 50 ms apart, then raises as before.
- `Store.save` (`state.json`), `save_plan` (`plan.json`) and `_write_project` (`project.toml`) all write through it now.

**New test:** `test_save_waits_for_a_reader` holds `state.json` open for 0.3 s while a save happens. I checked that the same situation with retries turned off raises the `PermissionError` from your report, so the test does catch it.

I restored the tracked `__pycache__` files that the test runs had modified.

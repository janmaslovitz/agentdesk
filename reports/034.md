## Brief

Part 2 of the AgentDesk Server. Needs task 1 (`agentdesk serve` with --host/--port/--data and the gateway-token header).

Build `agentdesk/gateway/` (new package, stdlib only if possible; threaded HTTP server like server.py) started by `python -m agentdesk gateway` (listens on a LAN address, default 0.0.0.0:8080 configurable in `<server-home>/server.toml`):
- User store `<server-home>/users.json` (atomic durable writes like core.write_json): username, role (admin|user), password hash (hashlib.scrypt with per-user salt, constant-time compare), disabled flag, created time, `home` (the user's data folder `<server-home>/users/<username>/`), assigned project slugs/accounts. Never log or return hashes.
- Login page (plain HTML, no external assets) at /login, POST sets a random session cookie (HttpOnly, SameSite=Strict, Secure when TLS), server-side session table with expiry, logout, brute-force throttle per user+IP, CSRF protection for state-changing calls (token or Origin check).
- After login: proxy EVERYTHING else (/, /api/*, static, chat polling, uploads/downloads incl. export zip, streaming responses) to that user's own instance. Instances: the gateway starts `python -m agentdesk serve --host 127.0.0.1 --port <free port> --data <user home> --auth-token-file <secret>` lazily per user, supervises/restarts them, stops idle ones after a configurable time (runs in progress must keep the instance alive), and sends the shared token header. Instance ports bind to loopback only. Users must never reach another user's instance or data: enforce by session->instance mapping only, never by a client-supplied id.
- Optional OS isolation: if `run_as_users = true` in server.toml, start the instance via `sudo -n -u agentdesk-<username>` / systemd-run (document, don't require).
- Optional TLS (`tls_cert`, `tls_key` in server.toml) for the gateway listener.
- Audit log of logins/failed logins/user changes (`<server-home>/audit.log`).
Tests (pytest tests): password hashing, login/logout/session expiry, throttle, isolation (user A cannot read user B's data through the proxy), proxy passes through POST bodies/binary, instance lifecycle with a fake instance. CHANGELOG under Unreleased. Keep dependencies out of requirements unless unavoidable.

**How it works**
- **Starting it:** `python -m agentdesk gateway` (or `agentdesk-gateway`) listens on 0.0.0.0:8080 by default. Settings are in `<server-home>/server.toml`, which is created with comments on first start. The server home is `--home`, else the `AGENTDESK_SERVER_HOME` variable, else `~/agentdesk-server`. The gateway never imports `core`.
- **Users:** stored in `users.json` with salted scrypt hashes, written atomically. Hashes are never returned or logged. You manage users from the command line: `gateway user add|list|passwd|disable|enable|remove|role|assign`. Passwords are typed at a prompt or read from stdin, never passed as arguments. Changing a password, disabling or removing a user ends that user's sessions. There is no admin web page for users yet.
- **Sign-in:** a plain HTML page at `/login`, with sign-out at `/logout`. Sessions are kept in the gateway's memory, so restarting the gateway signs everyone out. They expire after 12 hours, or 2 hours without a request. The cookie is HttpOnly and SameSite=Strict, plus Secure when TLS is on.
- **Wrong passwords:** after 5 failures for one user from one address (or 30 from one address across any names), that pair is locked out for 15 minutes.
- **CSRF:** a POST/PUT/PATCH/DELETE must come from the gateway's own origin or carry the session's token in an `X-AgentDesk-CSRF` header. The token is available from `GET /gateway/me`.
- **Audit:** sign-ins, failed sign-ins, lockouts, user changes and instance starts/stops go to `audit.log`.
- **Per-user instances:** each user gets their own `agentdesk serve` on a loopback port, started on their first request after signing in. Each start gets a fresh secret, read from a 0600 file (or from stdin when running as another OS user).
  - A crashed instance is restarted.
  - An idle instance is stopped after `idle_stop_minutes`, but not while a run, chat turn or build is in progress.
- **Proxy:** passes through every method, request bodies (binary included), and responses that have no Content-Length, which covers streaming and export zips.
  - The gateway's cookie and any client-sent control headers are removed before forwarding, the browser's Origin is replaced with the instance's own, and the instance can't set cookies.
  - Which instance a request reaches comes only from the server-side session.
  - Bodies sent with chunked encoding are refused with 411.
- **Optional features:** HTTPS via `tls_cert` and `tls_key`; `run_as_users` runs each instance as OS user `agentdesk-<username>` via sudo or systemd-run. The README explains the setup.
- **One addition to the dashboard:** `GET /api/busy` in `server.py`, which reports whether a run, chat turn or build is going on. The gateway uses it to decide whether an instance is idle.
- **Other changes:** the `gateway` entry in `__main__.py`, the package and script in `pyproject.toml`, a new "AgentDesk Server" section in the README, and a CHANGELOG entry under Unreleased.

**Tests** are in `tests/test_gateway.py`, using a fake instance in `tests/gateway_fake_instance.py`. They cover:
- password hashing and the user store
- session expiry and the lockout
- sign-in, sign-out and CSRF
- isolation: user A's file can't be read by user B, and forged headers don't change which instance is reached
- bodies, binary data, streaming, and the headers passed through
- restart after a crash; idle, busy and in-progress handling
- the user command line and TLS
- one test against the real `agentdesk serve`

The TLS test needs the `cryptography` package and skips without it; nothing was added to the requirements.

NOTES:
- The gateway (`python -m agentdesk gateway`) has user, CSRF and session info at `GET /gateway/me` (CSRF header `X-AgentDesk-CSRF`) and no admin web page for users yet; users are managed with `gateway user ...` (`agentdesk/gateway/cli.py`, `UserStore` in `users.py`).
- Instances are started with `--trust-proxy-auth` and receive `X-AgentDesk-User: <username>`; the user records' `projects`/`accounts` assignments are stored but not enforced yet.
- `GET /api/busy` in `server.py` decides whether an idle instance may be stopped; add new kinds of long-running work there.

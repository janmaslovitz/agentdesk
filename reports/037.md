# 037: Server hardening: enforce assignments, 0700 perms, file lock, verify spawned instance

Branch `auto/037` at 57a8ac0; tiers standard → hard.

## Brief

Follow-up from the security review of the gateway (agentdesk/gateway/). Check first what part 3 (admin cabinet) already did and do only what is missing:
(a) per-user `projects` and `accounts` assignments are stored but the proxy/instances do NOT enforce them: a user's instance must only see/use the Claude accounts assigned to it (write only those into that instance's settings.toml; never other users' keys or secrets), and project assignments must match what exists in the user's home.
(b) POSIX: chmod 0700 on every `users/<name>` folder and on server-home secrets (users.json, secret/token files, audit.log 0600).
(c) users.json writes are safe across processes (CLI + gateway): a file lock (fcntl on POSIX, msvcrt on Windows) around load-modify-save.
(d) after `_spawn` of an instance (instances.py), verify the listener on the chosen port really is our child before routing traffic or sending the gateway token: child pid alive AND an authenticated request with the gateway token answers as AgentDesk (e.g. /api/busy); otherwise kill/retry on another port.
(e) a login throttle regression test with parallel guesses (threads) proving at most max_failures password checks pass the throttle.
Tests: pytest tests. CHANGELOG under Unreleased. Do not bump the version.

## Worker summary

The worktree already had uncommitted changes from an earlier attempt that covered most of (a)–(e). I reviewed them, fixed the gaps below, and the full suite passes (`pytest tests`: 466 passed, 1 skipped). One test, `test_tls_listener_secure_cookie`, failed once with a connection reset during a gateway-only run. It passed six times on its own and in the full run, so it looks like a timing problem on a busy machine. I didn't dig into it.

**Already done by the earlier attempt (kept as is):**
- **(a)** Before each instance starts, its `settings.toml` is rewritten to list only that user's assigned accounts, and other accounts' key variables are left out of its environment. `assign` refuses projects that don't exist in the user's home.
- **(b)** POSIX permissions: `users/<name>` folders are 0700; `users.json`, `accounts.json`, `audit.log` and token files are 0600.
- **(c)** `users.json` changes take a cross-process file lock (`fcntl` on POSIX, `msvcrt` on Windows).
- **(d)** After `_spawn`, an instance is used only once its process is alive and the port answers an authenticated `/api/busy`. Otherwise it is killed, and if something else is on the port, another port is tried.
- **(e)** The throttle now reserves each attempt in one atomic step (`Throttle.begin()`), with a test that hits it from 40 threads.

**What I added:**
- **Gateway's own Claude keys:** `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` and `CLAUDE_CODE_OAUTH_TOKEN` from the gateway's environment no longer reach an instance unless an account assigned to that user names them. Before, any user could have used the gateway's key.
- **Stale project assignments:** a new `UserStore.prune_projects()` drops assigned projects that no longer exist. It runs when the admin cabinet removes a project, at every instance start, and before `gateway user assign` (otherwise a deleted project would block adding new ones).
- **Lockout bug:** a correct password on the last allowed attempt left the user locked out afterwards. A successful login now clears that lockout.
- **Password change page:** `/account/password` had the same parallel-guessing gap as login, so it now uses `begin()` too.
- **Tests:** a parallel-guess test through the real `/login` handler (30 threads; exactly `login_max_failures` password checks happen and the rest get 429), plus tests for the lockout fix, project pruning and the stripped variables. Two existing tests needed updating: `test_user_cli` now creates the project folder first, and the assigned-accounts test checks membership instead of an exact list.
- CHANGELOG Security entry under Unreleased updated; version not bumped.

When a user has no accounts assigned, the managed block is removed from `settings.toml`, so their instance falls back to the server's default Claude login. I left that as the admin cabinet designed it, but it doesn't strictly limit an instance to its assigned accounts.

NOTES:
- `users.file_lock` is not re-entrant: never nest `UserStore._locked()` (e.g. don't call `assign()` inside `_change()`), or it deadlocks.
- Login and password checks must call `Throttle.begin()` (reserves the attempt) and then `success()`; don't go back to `blocked_for()` + `failure()`.
- `app.CREDENTIAL_ENV` lists the Claude credential variables removed from instance environments unless an assigned account's `key_env` names them.

## Worker summary

Both bugs are fixed. `pytest tests` passes (234 tests); I haven't opened the page in a browser, so the header layout is checked from the CSS only.

**Mode buttons.** The header could not shrink the long Coworker badge, so it pushed into the buttons. I made the header wrap and set the Assistant/Coworker/Planner buttons not to shrink. The badge and model text now truncate with an ellipsis instead. I didn't touch `showMode()` or the mode names.

**Stuck "working…".**
- **Cause:** a stray `AssistantMessage` after a result set `busy` back to True. A real self-started turn (a finished background job) does the same, so the two look identical and I kept that behaviour.
- **Fix:**
  - A turn that was only inferred this way now clears itself once nothing has been heard for 45 seconds and no tool call is running. `/state` and `/chat` apply this when they report `busy`, so `chat_busy` goes false.
  - A real turn you start yourself is not affected by that timer.
  - A background turn that goes quiet for 45 seconds (with no tool running) will also drop the bar early.
- **Stop:**
  - `interrupt()` now always clears `busy`, so the bar hides.
  - It interrupts the client if there is one.
  - It always leaves a note: "■ Interrupted by you." during a turn, or "Nothing to stop: no reply is running." when idle.
  - The page also hides the bar the moment you press Stop.

I added three tests in `tests/test_live.py`: Stop when idle, Stop during a turn, and a stray late message not staying busy.

Edits to `server.py` and `index.html` kept their CRLF line endings.

NOTES:
- `Chat.auto_turn` marks busy set only by an unprompted CLI message; `settle()` / `is_busy()` clear it after 45s of silence with no tool call running.
- `Chat.interrupt()` always notes and clears `busy`, including when idle.

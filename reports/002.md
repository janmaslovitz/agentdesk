## Brief

Goal: let a user add a project from a plain folder without knowing git. When the folder isn't a git repo, or is a repo with no commits, AgentDesk offers local version tracking. If accepted, it sets up the repo and uses it like any other. Full spec: zz_agentdesk_next.md section 3 and the Task 002 file in data/projects/agentdesk/tasks/002-plain-folder-local-git.md (read-only context).

## Worker summary

Adding a project from a plain folder now works behind an opt-in. All 5 new tests pass, and there were no other tests in the repo to run. I didn't run the dashboard prompt in a browser or the `--local-git` CLI path by hand.

- **`core.py`:** `add_project` takes `local_git=False`. Without it, a folder with no `.git`, or a repo with no commits, raises `NeedsLocalGit` (reason `not_a_repo` or `no_commits`) and changes nothing.
  - With `local_git=True`, it runs `git init` if needed and writes the specified `.gitignore` only if none exists.
  - It then makes the single commit "AgentDesk: starting point" and uses the current branch as the base, ignoring the `base` argument.
  - If `user.name` or `user.email` is unset, it sets `AgentDesk <agentdesk@localhost>` with `git config --local`. No remotes, no push, no global config.
  - A repo that already has commits is left untouched, including no new commit.
- **`server.py`:** `POST /api/projects` returns `{needs_local_git, reason, message}` when setup is needed, and accepts `local_git: true` on the re-POST.
- **`__main__.py`:** `add-project` has a new `--local-git` flag. Without it on a plain folder, the command prints an explanation and exits non-zero, with no prompt.
- **`web/index.html`:** `addProject()` shows a confirm dialog, "Set up local version tracking (stays on this computer)?", and re-submits with `local_git: true` if accepted.
- **`README.md`:** the Projects section now has a note that tracking is local only, nothing is pushed and no remote is added.
- **Tests:** the new `tests/test_local_git.py` covers:
  - a plain folder refused without the opt-in;
  - the full setup, including the `.gitignore` contents, the local identity, no remote, and a worktree created from the base branch;
  - an existing `.gitignore` kept;
  - an empty repo getting only the first commit;
  - an existing repo with commits staying unchanged.

  They use a temp dir and patch `core.DATA`, with global git config isolated.

Open question: an existing repo with commits still doesn't check that the `base` you pass exists. That was already the case, so I left it.

NOTES: pytest isn't in requirements.txt; tests live in `tests/` and patch `core.DATA` (read from `AGENTDESK_HOME` at import).
NOTES: `core.add_project(..., local_git=True)` is the only path that runs `git init`; `core.NeedsLocalGit` signals setup is needed.

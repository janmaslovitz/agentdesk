## Worker summary

Project export and import now work as an offline `.zip`, through git, and from the CLI. `python -m pytest tests` passes (94 tests, about 37s), run twice. I did not run the dashboard dialogs.

**What changed**
- **`core.py`:** new `export_project`, `export_to_git`, `import_project`, `clone_for_import`, `NameClash` and `BadExport`.
  - **What is exported:** only an allowed list of files: `project.toml`, notes, state, tasks, reports and chat history. `agentdesk.log` is added only with "include logs". Worktrees and pid files are never exported.
  - **Config rewriting:** `account`, the repo path and the worktrees path are removed from `project.toml`, and secret-looking `[gates.env]` values are blanked. Known key values, login folder paths and `sk-ant-…`/GitHub tokens are replaced with `[redacted]` in every exported file.
  - **Git export:** commits only `.agentdesk/` in the project's repo, or `<config repo>/<slug>/`, and pushes only when asked. It never force-pushes, never changes remotes, and pushes to origin (or the first remote).
  - **Import:** accepts a zip, a folder or a git repo. It rejects zip-slip paths, unknown manifest versions and oversize files (20 MB per file, 100 MB total, 5000 entries). It never overwrites a project. On a name clash it raises `NameClash` with a free name.
  - **After import:** the repo path is set to the local one given at import, and the account is set only if it exists locally.
- **`server.py`:**
  - `POST /api/projects/<p>/export` returns zip bytes, writes to a given `file`, or does a git export. Git export needs `confirm: true`, and every export is refused while a run is active.
  - `POST /api/projects/import` takes a raw zip upload or JSON naming a source path, a source URL, and a repo path or URL. A name clash returns `{name_clash, suggested}`.
- **`__main__.py`:** `export PROJECT FILE [--logs]` and `import-file FILE --repo PATH [--name N] [--account A]`. The CLI refuses on a name clash. The existing `import` command is unchanged.
- **`index.html`:** Export button per project, Import button on the project list, a save-as zip flow, a git-commit dialog, and a rename prompt on name clash.
- **`tests/test_export_import.py`:** 7 tests covering:
  - zip round trip, and git round trip through a local bare repo;
  - a config-repo export;
  - a secret scan that fails if the key, login path or env-var name appears in an export;
  - zip-slip, oversize, bad version and name clash;
  - the CLI, and the HTTP routes including the run-in-progress refusal.

**Not verified**
- The UI dialogs (save picker, rename prompt, clone fields) need a manual check in the dashboard.
- Cloning a remote URL was only tested with a local bare repo.
- Chat history is held in memory only in this codebase, so nothing is exported for it today. The export includes `chat*.json` files if any exist, redacted.
- If the repo-clone-URL import fails after the clone step (for example on a name clash), the cloned folder stays. Retrying needs a new or empty folder, or the repo path without the URL.
- Zip import has no limit on total uncompressed size beyond the 100 MB total cap.

- Tests that need a second `AGENTDESK_HOME` monkeypatch `core.DATA`; `core.DATA` is the only data-path source.

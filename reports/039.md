## Brief

The AgentDesk server host has a hard 512 GB disk shared by all users, so builds, worktrees and package caches must be managed strictly so nothing bloats. Today agentdesk/hygiene.py is per-project and cargo-centred (target dirs, worktrees, logs; auto=false by default). Extend it to a SERVER-wide budget, reusing hygiene's safety rules (never follow symlinks, never delete outside configured locations or while a run uses the folder, refuse when unsure). Check what earlier server tasks already did.
1. Server budget in server.toml: `disk_total_gb` (default 512), `disk_reserve_gb` (free space that must always remain, default 40), soft limit (e.g. 80% -> warn + auto-clean), hard limit (e.g. 92% -> refuse to start runs/clones/imports/uploads, with a clear message in UI/CLI; running work is not killed). Measure with a background, cached walker (never in request path), also report real filesystem usage (shutil.disk_usage) since other things use the disk.
2. Per-user quotas: `quota_gb` default plus per-user override (admin cabinet + `agentdesk-server user quota`). Count the user's home: repos, worktrees, build targets, caches, chats, logs. Over quota -> that user's new runs/clones are refused, auto-clean for their data first; show usage bars in the user's dashboard header (small) and the admin cabinet (per-user table, sortable, with top consumers).
3. Build artifact policy (defaults ON on the server, unlike the desktop): auto clean stale target/build dirs (cargo target, node_modules of finished worktrees if reproducible, python venv/.pytest_cache/__pycache__, dist/build, gradle/maven build dirs) by age and by size caps per project; finished/merged worktrees removed after N hours (keep branches); at most K concurrent worktrees per project; remove half-created worktrees. Generalise the cargo-only code via a small registry of "build kinds" (markers + paths + safe-to-delete rules) rather than copy-paste; keep cargo behaviour and tests intact.
4. Package/dependency caches shared across users where it is safe, to avoid N copies: set per-instance env so CARGO_HOME registry/git, npm cache, pip cache, uv cache, go mod cache, gradle cache point at ONE server-wide cache dir (`<server-home>/cache/<tool>`) with size caps and LRU/age pruning (cargo-cache style by atime/mtime; `npm cache clean`/`pip cache purge` equivalents only inside that dir) and per-tool caps in server.toml. Shared caches must be content-addressed tools only (do not share a mutable build target between users). Option to hardlink-dedupe identical files in the cache. Make CARGO_TARGET_DIR optionally per-user shared across that user's worktrees of one project to cut duplication, with a cap.
5. Git object bloat: `git gc --auto`/prune for repos on a schedule (low priority, off-peak, never during a run), shallow/partial clone option when importing from URL (`clone_depth` setting, `--filter=blob:none` option), warn for large files committed by agents (> N MB) in the report.
6. Logs/chats/exports: cap sizes (hook into the log rotation from the reliability task), exports/imports temp dirs (`<server-home>/imports`, upload spool) cleaned after use and after 24 h, upload size limit enforced.
7. Visibility and safety: admin cabinet "Storage" page: totals, per-user, per-project, per-cache, what the next auto-clean would delete (dry-run list) and a button to run it; audit-log every automatic deletion (what, how many bytes). A dry-run mode (`agentdesk-server clean --dry-run`) and `doctor` warnings when above soft limit.
Tests (pytest tests): quota/limit logic with fake sizes, refusal at hard limit, clean never touches anything outside configured roots or active runs, cache pruning in a temp dir, worktree cap, symlink safety. CHANGELOG under Unreleased; document in docs/SERVER.md (sizing guide for 512 GB, defaults, how to tune). Do not bump the version.

**How the pieces fit:** the gateway measures disk use in a background thread and caches the result in `<server-home>/storage.json`. For each user it writes `<user home>/server-policy.json`, which that user's instance re-reads. The policy carries the refuse/allow decision, the server's cleanup settings, the shared-cache environment and the clone options. So the dashboard, the auto-runner and the admin cabinet all see the same answer.

- **Budget and quotas** (`agentdesk/storage.py`, new `server.toml` keys): 512 GB budget, 40 GB reserve, soft limit 80% (warn and clean automatically), hard limit 92%.
  - At the hard limit, or when a user is over quota, new runs, clones, imports and uploads are refused with a message; running work is not stopped. Uploads are refused before the file is received.
  - Usage counts the real disk usage, since other programs use the disk too.
  - Quotas default to 50 GB per user and can be set per user in the cabinet or with `agentdesk-server user quota NAME GB|default`.
- **Build cleanup** (`agentdesk/hygiene.py`):
  - A small registry of build kinds: cargo, node_modules, Python venvs and caches, dist/build, gradle, maven. Cargo behaves as before and its existing tests pass unchanged.
  - Worktrees of done tasks are removed after 24 hours idle, keeping the branch. At most 6 worktrees per project; at the cap the next task waits. Half-created worktrees are removed.
  - Off-peak `git gc --auto` at low priority, never during a run, and a report warning for large committed files.
  - Defaults are on for server instances only; desktop behaviour is unchanged.
- **Safety:** the never-follow-links and stay-inside-the-root delete helpers moved to a new `agentdesk/fsutil.py`, which the gateway also uses. Build folders are only deleted when git says they are ignored and contain no tracked files. A lock file stops the gateway's cleanup and the instance's cleanup from running on the same project at once.
- **Shared caches:** npm, pip, uv, Go modules, cargo registry/git and gradle modules live in `<server-home>/cache/<tool>`. Each has a size cap and is pruned least-recently-used first, only inside its own folder. Optional settings:
  - hard-link dedupe of identical cache files;
  - one shared cargo target per user and project;
  - shallow or partial clones from a URL.
- **Visibility:**
  - A Storage tab in the admin cabinet: totals, a sortable per-user table with top consumers, per project, per cache, a dry-run list of the next cleanup and a "Clean now" button.
  - A usage bar in each user's dashboard.
  - New commands `agentdesk-server storage [--scan]` and `clean [--dry-run]`; `doctor` warns above the soft limit and fails at the hard limit.
  - Every automatic deletion goes to `audit.log`.
- Docs: a "Disk budget" section in `docs/SERVER.md` with a 512 GB sizing guide, and a CHANGELOG entry under Unreleased.

Decisions for you:
- **Policy beats `settings.toml`:** on a server, the policy's cleanup settings override the user's own `settings.toml`. The default `settings.toml` template writes `auto = false` explicitly, so the server defaults would otherwise never take effect. A project's own `project.toml` still wins.
- **No sharing under `run_as_users`:** with `run_as_users` on, package caches stay per user, because separate OS accounts can't safely share one folder.
- **Worktree removal is stricter:** it now refuses while any process (not just cargo) is working in that worktree.

## Worker summary

I reworked the task detail panel. Clicking a task now shows four collapsible sections in order: Prompt, Orchestrator handoff, Agent work and Agent report. `pytest tests` passes (243 tests). There's no formatter configured in the repo, so I matched the existing style by hand.

**Recording (agentdesk/core.py)**
- **New log file:** each task gets an append-only log at `data/projects/<slug>/runs/<id>.jsonl`. It's written from the message loops in `route()` and `work()`. It records each run's start (tier, model, effort, attempt), tool calls with a short input summary, the file path for Edit/Write, tool errors, capped text snippets, results (turns, tokens, cost), check pass/fail, check retries, network retries, the routing decision and escalations.
- **Size limits:** each text field is cut at 400 characters. Once a task's file passes 512 KB, only the key events (start, result, check, retries) are still added. A failure to write the log never fails a run.
- **Not via `write_atomic`:** the brief asked for it on shared files, but this file is append-only. Each event is a single one-line write, and the reader skips a half-written last line.
- **Effort** is now stored on every run entry in state.json, for both router and worker runs.
- **Moved functions:** `tool_summary` and `result_text` moved into core so the log and the chat share them. server.py keeps aliases with the same names.
- **Export choice:** I treat `runs/` as logs, like `agentdesk.log`, because it holds commands and model text. It's exported only when "include logs" is on (redacted like everything else) and is accepted back on import.

**Endpoint (agentdesk/server.py)**
- `GET /api/p/<slug>/task/<id>` now returns the prompt, the handoff (tier, model, effort, router reasoning, brief, dependencies, branch, worktree, commit, start/finish times and each run), the activity timeline, totals, the last failure and the report.
- The run rows come from the same helper `/state` uses (`task_row`), so they aren't built twice.
- Tasks that ran before this change have no timeline file, so the panel falls back to that task's lines in `agentdesk.log`.

**Panel (agentdesk/web/index.html)**
- I edited it byte-wise and kept the CRLF line endings; the diff only touches the panel code and its styles.
- **What opens by default:** for done tasks the report opens and the rest stay collapsed. The brief didn't say what to open for other tasks, so I chose: Prompt for pending tasks, Agent work for running or blocked ones.
- **Polling:**
  - The panel only fetches again when the task's status or run count changes.
  - If nothing changed, the page isn't touched, so scroll position and open sections stay as they were.
  - Sections you open or close stay that way when the panel does rebuild.
- **Long content:** long text wraps and scrolls inside a box with a maximum height. I also raised the panel's height limit from 360px to 560px to fit four sections.
- Empty states read "Not started yet", "No runs yet", "No report yet", and so on.
- **Escaping:** all text is escaped, and the report goes through the page's existing escaping markdown helper.
- **Smoke test:** I also checked the render in Node with fake data: escaping, which sections open, no refetch or scroll jump when nothing changed, and a refetch when the run count changed.

**Limitation:** a running task's timeline doesn't update live in the open panel. As the brief specified, it only refetches when a run finishes or the status changes; clicking the task again fetches it straight away.

**Tests:** the new `tests/test_task_detail.py` covers the log writer (size limits, half-written lines), the log being written during mocked `work()` and `route()` runs, the endpoint for a pending task, a finished task and the old-log fallback, the export choice, and a source-text check of the panel.

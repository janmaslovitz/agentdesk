# 035: Server 3/4: admin cabinet (users, projects, instances)

Branch `auto/035` at 0c0cd08; tiers standard.

## Brief

Part 3 of the AgentDesk Server. Needs the gateway (task 2). Add an admin cabinet served by the gateway at /admin (role admin only, server-side check on every route; a normal user gets 403):
- Users: list, create (username, role, initial password), reset password, disable/enable, delete (with a confirm; deleting data is a separate explicit checkbox, default keeps the data folder), change own password for every user at /account.
- Projects per user: list each user's projects (read via the user's instance API or its data folder), create a project for a user from a git URL (clone on the server) or an uploaded .zip export (reuse core.import_project / clone_for_import), remove a project, show size on disk.
- Claude accounts: admin defines accounts (API key via key_env / config_dir login) in the server settings and assigns them to users; users cannot see keys. Never display secrets.
- Instances: status (running/idle/stopped, port, uptime, active runs), start/stop/restart, view the instance log tail; server health (disk free, version).
- Audit log viewer (read-only, last N).
UI: same visual style as the dashboard (agentdesk/web), plain HTML/JS, consistent alignment, works at narrow widths, light/dark like the dashboard. Add a link "Admin" in the gateway chrome for admins only (small top bar injected by the gateway, don't fork index.html). Tests for authorization of every admin route and for the user/project operations. CHANGELOG under Unreleased.

## Worker summary

The admin cabinet is in at `/admin`, and every admin route checks the role on the server (a normal user gets 403). The new admin tests plus `test_gateway.py` and `test_serve.py` pass (68 tests). I did not run the whole suite, and I did not open the pages in a browser. I only syntax-checked the page JavaScript with `node --check`, and no formatter was available (`ruff` isn't installed), so nothing was auto-formatted.

- **Users:** list, create, reset password, disable/enable, change role, and delete. Delete asks you to type the user name, and deleting the data folder is a separate checkbox that is off by default. You can't disable, delete or demote yourself or the last enabled admin. Everyone can change their own password at `/account`, which signs them out everywhere.
- **Projects:**
  - **Listing and size:** projects are listed from each user's data folder, with size on disk.
  - **Adding:** add one from a git URL (cloned on the server) or an uploaded `.zip`. A new helper `agentdesk/gateway/projtool.py` runs these as a child process with that user's `AGENTDESK_HOME`.
  - **Plain repos:** a git repo that has no AgentDesk export becomes a plain project.
  - **Removing:** removing a project keeps the cloned repo unless you tick the box.
- **Claude accounts:**
  - **Definitions:** admins define them in a new `<server-home>/accounts.json`. An API-key account stores only the name of the environment variable that holds the key, never the key.
  - **Assignment:** assigning an account writes it into that user's `settings.toml` as a managed block. Users only see the account names.
- **Instances and server:** state (running/idle/stopped), port, uptime, active runs, start/stop/restart, a log tail with secrets redacted, and free disk and version.
- **Audit log:** a read-only view of the last N events (up to 2000).
- **Dashboard bar:** the gateway adds a small floating bar to the dashboard's HTML pages. It shows "Admin" (admins only), "Account" and "Sign out", and `index.html` is untouched.
- **Style:** the UI is plain HTML/JS in the dashboard's colours, light/dark, and works at narrow widths.
- **Docs and tests:** CHANGELOG (Unreleased) and the README gateway section are updated. `tests/test_admin.py` covers all 26 admin routes for 403 and the user, account, project, instance and `/account` operations. I also added a `/page` route to the fake instance.
- **Other edits:** `users.remove` gained a `delete_data` option, and `InstanceManager.busy_info()` returns the full `/api/busy` answer.

With `run_as_users`, project operations are wrapped in `sudo -n -u agentdesk-<name>`, and I have not tried that.

NOTES:
- The gateway never imports `core`. Anything that needs a user's projects runs `python -m agentdesk.gateway.projtool` with that user's `AGENTDESK_HOME` and reads one JSON line from stdout.
- Server-wide Claude accounts live in `<server-home>/accounts.json` and are synced into the user's `settings.toml` between `# >>> agentdesk-gateway accounts` markers. Assigned accounts replace the built-in list, so the default account disappears once any are assigned.
- Admin routes are handled by `admin.dispatch()`, called in `Handler.route()` after the CSRF check and before the proxy.

## Worker summary

The chat transcript now persists to `data/projects/<slug>/chat.json` and reloads when a `Chat` is built for that project. The full suite passes (128 passed), and `tests/test_chat.py` passes (33 passed).

**Diff summary** (`agentdesk/server.py` +20/-1, `tests/test_chat.py` +51)
- **`Chat.load_history()`**: reads `chat.json` and returns its contents if it parses as a list. A missing, unreadable, bad-JSON, bad-UTF-8, or non-list file returns `[]`, and it never raises. `Chat.__init__` calls it, so loading happens per project on first `chat(p)` use.
- **`Chat.save_history()`**: writes the full list as UTF-8 with `ensure_ascii=False` to `chat.tmp`, then `os.replace`s it over `chat.json`, following the `core.py` `save()` pattern.
- **`ask()`**: calls `save_history()` right after the user append and again after the assistant append. Both appends are already inside `self.lock`.
- **`reset()`**: when `keep_history` is false, it also does `chat.json.unlink(missing_ok=True)`. The mode-switch path (`keep_history=True`) leaves the file alone.
- **Tests added**:
  - a round trip through the real `ask()` (with `_ask` stubbed), then a fresh `Chat` for the same project reloads the same transcript;
  - `reset()` removes the file and a new `Chat` is empty;
  - the mode switch keeps the file;
  - five bad-content cases (bad JSON, empty file, a dict, a bare string, bad UTF-8) give `[]`;
  - a missing file gives `[]`.

**Where the approach differs from the brief**
- **Entry shape**: the assistant entries also keep `model` and `tokens`, because `_answer()` already returns them and the existing code stores the whole reply. I did not strip them down to `tools` and `cost`.
- **Formatter**: the repo has no formatter config, and neither ruff nor black is installed, so nothing was reformatted. I kept to the file's existing style.
- **Restart test**: I ran unit tests only, not an end-to-end server restart with the dashboard.
- **Environment**: tests run under the `conftest.py` temp `AGENTDESK_HOME`. I did not touch the live checkout or its `data/`, and I ran no git remote commands.

NOTES:
- `chat.json` stores the full assistant entry (`text`, `tools`, `cost`, `model`, `tokens`), not only `tools` and `cost`.
- `Chat.load_history()` runs in `Chat.__init__`, so each project loads its transcript on first `chat(p)` use. `reset()` deletes `chat.json`; `reset(keep_history=True)` keeps it.
- A restart during an in-flight answer leaves a saved user message with no reply. Nothing repairs this on load.

**What changed**
- **Coworker sessions (`server.py`)**:
  - Model, effort and budget come from `[chat.coworker]` (default sonnet, effort medium).
  - It works in its own worktree `<worktrees>/cowork` on branch `auto/cowork`, created from the base branch on first use. It can read the project folder too.
  - Shell commands and the run/queue tools run without approval cards.
  - Switching modes starts a new session but keeps the messages on screen.
- **Budget per message**: each Coworker message runs in a fresh Claude process that picks up the conversation, with `max_budget_usd = budget_usd`. When it's hit, the answer ends with "Stopped: this message spent $X and reached the Coworker budget of $Y per message…".
- **Usage pause**: if the account's last reading is at or over `pause_at_utilization`, the Coworker answers "Paused: …" instead of starting. If a reading crosses the threshold mid-message, it stops there and says so.
- **Guard (`core.py`)**: same deny list as the workers. Edits are allowed only in its worktree, `tasks/` and `notes.md`. I also made the worker guard a bit stricter: paths are normalised, so `wt/../other` and a sibling folder like `0040` vs `004` no longer pass.
- **Settings**: `[chat.coworker]` (model sonnet, effort medium, budget_usd 2.0) is added to the built-in defaults and to `data/settings.toml`, without changing any existing values.
- **Dashboard (`index.html`)**: the header shows the badge "Coworker: runs commands without asking", the model and effort, and a note with the worktree and budget.
- **README** describes the Coworker and its limits. New tests are in `tests/test_coworker.py`.

**Spec deviations and things to know**
- **Gap found in the guard**: the Claude CLI approves commands it considers read-only (like `echo`) without ever calling `can_use_tool`. The live test showed a denied `echo` running anyway. I fixed it for the Coworker by adding a check that runs before every tool call. **The workers still rely on `can_use_tool` alone**, so they have the same gap; the real deny patterns (push, remote, publish) aren't read-only commands, so I left workers unchanged.
- **Stricter than the spec**:
  - In the project folder the Coworker may only edit `tasks/` and `notes.md`, not the whole folder.
  - Shell commands that mention `project.toml` or `settings.toml` are refused, because the gate commands in `project.toml` run without any guard.
  - The Coworker doesn't load the project's `.claude` settings, since those could allow commands past the guard.
- **Budget overshoot**: the budget is checked after each model turn, so a message can go over by one turn.
- **Task 003 bug fixed**: the chat added the CLI's session running total as each message's cost, so later messages were overcounted. Each message now records the difference, in both modes.

NOTES:
- The Claude CLI's `total_cost_usd` is a running total for the session (even after resuming it), while `max_budget_usd` counts only the current process; so the Coworker uses a fresh process per message.
- The CLI approves read-only commands without calling `can_use_tool`; only a PreToolUse hook sees every call (the Coworker has one, the worker `core.guard` doesn't).
- `__pycache__/*.pyc` files are tracked in git; run tests with `PYTHONDONTWRITEBYTECODE=1 ... -p no:cacheprovider` or restore them afterwards.

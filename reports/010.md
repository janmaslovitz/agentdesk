## Brief

Goal: the Assistant chat keeps a short running memory across server restarts. Add per-project `chat_memory.md` (plain Markdown, sections: Decisions, Facts about the project, Open questions, User preferences; capped at about 1500 words). Keep it separate from `chat.json`, which is display-only and never sent to the model.

Files:
- agentdesk/server.py
  - `CHAT_PROMPT` (~line 111) and `Chat._assistant_options()` (~375): the system prompt is built here.
  - `Chat._client()` (~401) and `_close()` (~412): session creation. Inject memory here so each new session gets the latest content.
  - `Chat._ask()` (~423-478): where the reply is produced. It runs on the SDK loop. The `generation` counter (~252, ~466) guards against stale sessions.
  - `Chat.ask()` (~484): holds `self.lock`, appends history, and returns the answer. The memory update belongs after the reply is saved to `chat.json`, inside this lock.
  - `Chat.reset()` (~501): clears history, the session, and now memory.
  - Use `self.p.path("chat_memory.md")` for storage. Write via a temp file, then replace.
- tests/test_chat.py: the `chat` fixture (~33) and `start()`/`wait_pending()` helpers.

Constraints:
- No CLAUDE.md or AGENTS.md was found at the repo root. Follow the existing style in server.py.
- The memory-update call must use no tools and must not touch `permission()` or `can_use_tool`. Use the chat model setting or haiku. Use a one-shot, tool-free call; do not reuse the chat session.
- The updater's input is the old memory plus the last user and assistant messages. Its output is the full updated memory in the fixed format. Reject an empty reply, a reply missing the section headings, or one over the cap after one retry. Keep the old memory in each of those cases.
- Never store secrets or file contents. Only key facts.
- Log failures and keep the chat working. A failed update must not change the reply shown.
- The updater's cost stays out of `chat_usage.json`, so note in the report that it is not counted.
- Inject memory under a heading like "What you remember from earlier conversations" when the session is created.
- After `reset()`, both files are empty and the next session has no memory.
- A session recreated after an error gets the same memory.

## Worker summary

The Assistant chat now keeps a short running memory in `chat_memory.md` per project. Memory is injected into each new session and updated after each reply. The full suite passes (138 tests), with the new memory tests in `tests/test_chat.py`.

**How it works** (changes in `agentdesk/server.py`):
- **Format:** the memory is plain Markdown with the sections Decisions, Facts about the project, Open questions and User preferences. The updater is asked to stay under 1300 words, and the hard cap is 1500.
- **Injection:** when a session is created, the memory is appended to the system prompt under "What you remember from earlier conversations". A session recreated after an error reads the file again, so it gets the same memory. I added this to the Coworker prompt as well as the Assistant's.
- **Update:** after the reply is saved to `chat.json`, still inside the lock, one tool-free model call (`memory_call`) gets the old memory plus the last user and assistant messages. It uses the chat model setting, or haiku if that is empty. It runs only after a successful reply; a failed `ask` leaves the memory alone.
- **Rejection:** an empty reply, one missing a section heading, or one over the cap gets one retry. After that the old memory is kept and the failure goes to `agentdesk.log`. Any exception is logged the same way, and the reply shown to the user is unaffected.
- **Writes:** memory is written to a temp file and then replaced.
- **Permissions:** `permission()` and `can_use_tool` are untouched; the call has all tools disallowed.
- **Reset:** `reset()` deletes both `chat.json` and `chat_memory.md`. A mode switch (`keep_history=True`) keeps the memory.
- **Test fixture:** in `tests/conftest.py` an autouse fixture stubs `memory_call`, so existing tests never make a real call.

**Not counted:** the updater's cost is not added to `chat_usage.json`.

**Not run:** the real restart check (tell a fact, restart the server, ask about it) is manual and was not run. I did not start a server on 8765. `ruff` isn't installed here, so no auto-formatter ran. I kept to the existing style by hand.

NOTES: `chat_memory.md` is separate from the display-only `chat.json`; `Chat.update_memory` runs inside `ask()`'s lock and goes through the module-level `server.memory_call`, which tests patch.
NOTES: Memory-update cost is deliberately not counted in `chat_usage.json`.

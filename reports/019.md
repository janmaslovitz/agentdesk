Use port 8799 for any dashboard test. Do not start real worker runs: fake the run starter in tests.

GOAL: every project (existing and new) is managed by a background loop in the dashboard server, one pass ~every 30 s:
1. Start next: if no run is going for the project and a pending task has all dependencies done, start it via the same path as run_next (server.py ~line 349). One run per project.
2. Stale recovery: task `working` whose runner pid is gone (check project runner.pid / runner(p).running(), server.py ~92) → set to pending, last_failure "worker exited unexpectedly (code N)" when known. Example: exit 129 left task 008 stuck.
3. One automatic retry for crash/kill/infrastructure end (not failed gate, not task-level failure). After that, stop and flag.
4. Skip when core.usage_paused(acct) is set (core.py ~636); never start when the project has a pending approval.
5. Flag, never act: failed gates (run_gates ~568), repeated failures, merge conflicts, done tasks whose branch is unmerged and unreviewed (task 015 merge state). Flags show in a "Needs attention" list (count badge; reason, task id, button to open report/log) and are appended to the project log.
6. Never merge, push, delete branches or change remotes automatically.

PURE FUNCTIONS in core.py (testable with fake state): next_startable, recover_stale, classify_failure, attention_items.

SETTINGS: settings.toml [autorunner] enabled=true, interval_s=30, retry_crashed=1 (DEFAULT_SETTINGS string ~line 42; settings() ~112). Per-project override in project config via _project_cfg/_write_project (~271-285) — write nothing per-project unless the user changes it. A project with no override is enabled. add_project (~366) must not write autorunner keys.

API: GET /api/attention; POST /api/projects/<p>/autorunner (per-project on/off; also a global toggle). Status string visible in UI: "Auto: on" / "paused: usage limit" / "waiting: needs attention".

LOOP: start in server.py main() (~902) only in the single-instance server-owning process (reuse existing single-instance logic); no double starts after restart. QUIT event exists (server.py) — the loop should stop on it.

UI: agentdesk/web/index.html — per-project toggle, global toggle, status, Needs attention list.

CONSTRAINTS: no model/API calls from the loop; it only reads state and checks pids. Mutating POST routes need confirm:true where the existing pattern does. Don't break the existing run_next path.

TESTS (tests/): unit tests for the four pure functions with fake state; a test that a freshly added project (add_project) is auto-managed with defaults and writes no per-project autorunner keys; a test that retry happens once then flags; a test that gate failures and unmerged done branches produce attention items and no merge/push is called. Full pytest must pass.

## Worker summary

The auto-runner is in, and the full suite passes (`python -m pytest tests`, 90 passed). I didn't run a real worker or open the dashboard UI. I worked in this task's worktree with a temp `AGENTDESK_HOME`.

**What changed**
- **`agentdesk/core.py`**
  - New `[autorunner]` default in settings (`enabled = true`, `interval_s = 30`, `retry_crashed = 1`).
  - `autorunner_cfg` reads the code defaults, then the settings file, then the project's `project.toml`. `set_autorunner` writes the global or per-project toggle, and only when the user changes it.
  - The four pure functions: `next_startable`, `recover_stale`, `classify_failure`, `attention_items`.
  - Helpers `pid_alive` and a read-only `branch_merged`.
  - `add_project` is untouched, so new projects write no autorunner keys.
- **`agentdesk/server.py`**
  - A `QUIT` event and an `autorun_loop` thread started in `main()`, only after the port check, so only the process that owns the port runs it. The loop waits one interval before its first pass, so a short-lived dashboard never acts.
  - Each pass, per project:
    - **Recover:** a task left `working` with no live run goes back to `pending` with last_failure "worker exited unexpectedly (code N)".
    - **Flag:** problems are written once to the project log.
    - **Start:** the next ready task starts through `runner(p).start`, but only if the project is enabled, not usage-paused, has no pending approval and no run going.
  - Routes: `GET /api/attention`, `POST /api/projects/<p>/autorunner` and a global `POST /api/autorunner`. The overview now carries each project's status string (`Auto: on`, `paused: usage limit`, `waiting: needs attention`) and the attention list.
- **`agentdesk/web/index.html`**: a per-project toggle with its status, a global toggle in the sidebar, and a "Needs attention" list with a count badge and an Open report/log button.
- **`tests/test_autorunner.py`**: 9 new tests, listed below.

**Decisions to check**
- The loop starts the specific task with `run <slug> <id>` rather than `run --max 1`, so it never picks a task that is already flagged. It still goes through the same `runner.start` as run_next.
- I did not add a `confirm: true` requirement to the new POST routes, because none of the existing routes use it.
- Task 015's merge state isn't in this tree, so I used my own checks:
  - "Unmerged" means the task's branch exists and isn't an ancestor of the base branch (read-only `git rev-parse` / `merge-base`).
  - "Reviewed" is a `reviewed` flag in the task's state entry, and "conflict" is a `merge: "conflict"` entry. Nothing writes either today, so they need wiring to task 015's real fields.

**What changed:**
- **`agentdesk/hygiene.py` (new):** measuring, the cleanup plan and the deletion code, with a background cache.
  - Measuring is fast (`os.scandir`) and never follows symlinks or junctions.
  - Every deletion is checked again right before it happens. It refuses anything that isn't clearly a target dir, anything outside the project's folders, anything holding `.git`/`Cargo.toml`, and paths through a link.
  - It does nothing while a run or build is active for the project, or while a cargo/rustc/rustup process uses the folder. If the process list can't be read, it skips.
  - Read-only files and long paths are handled.
  - Worktrees are removed only with `git worktree remove --force` + prune, and only when they have no uncommitted or untracked files.
  - Each action and the space it freed goes to the project's `agentdesk.log`.
- **`core.py`:** the `[hygiene]` settings (defaults added to the default settings.toml) and a validating reader. A bad value is ignored and logged, never a crash. project.toml is never edited.
- **`server.py`:** a background job, `GET /api/p/<slug>/disk` (reads the cache only) and `POST /api/p/<slug>/disk/clean` (dry run by default; deleting needs confirmation). The auto-runner waits while a cleanup runs.
- **`index.html`:** a Disk section per project, a ⚠ and total in the project list, and README/CHANGELOG entries.

**Not like the brief:**
- **Shared-target advice:** for Sintec.PDF it only flags the one target shared by 20 worktrees, because `CARGO_INCREMENTAL` and debug info are already off there.
- **Without psutil:** psutil isn't installed here, so on Windows the PowerShell fallback can't see a cargo process's working folder. To avoid blocking every cleanup whenever any cargo runs, a cargo counts as "building elsewhere" only if a rustc under it shows an `--out-dir` outside the folder. With no such evidence it still blocks. `pip install psutil` makes this check exact; I didn't add it to `requirements.txt`.

There's no formatter configured in the repo, so none was run.

**How to try it by hand:**
1. Start the dashboard, pick Sintec.PDF and scroll to **Disk**. The first measurement takes a few seconds; **Measure again** refreshes it.
2. Press **Clean up**. It shows a dry run: what would be deleted and how many GB, with checkboxes, and deletes nothing.
3. To delete, untick what you want to keep, press **Delete selected** and confirm. Results show in the section and in the Activity log.

`[hygiene] auto = true` in a project's project.toml makes the background job clean up by itself every `interval_min` (default 30 minutes).

NOTES:
- Disk hygiene is in `agentdesk/hygiene.py` (settings `core.hygiene_cfg` / `HYGIENE_DEFAULTS`); dashboard reads `/api/p/<slug>/disk` from the cache only, and cleanup runs in a background job (`hygiene.start_clean`).

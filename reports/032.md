## Worker summary

I reworked both dialogs and added the branch export. `pytest tests` passes (380 tests). I haven't looked at the dialogs in a window, so the layout at default and narrow sizes, and in light and dark, is unchecked. I also haven't tried the native Browse picker in the desktop window. No formatter is configured in the repo, so I ran none.

- **Branch export:** `core.export_to_branch(p, include_logs, push)` commits the export to `agentdesk-export/<slug>` of the project's own repo.
  - **Checkout untouched:** it builds the commit in a temporary index and folder, so your checkout, current branch and uncommitted changes are never touched. It refuses if that branch is the one currently checked out.
  - **Layout:** the export sits at the branch root (`manifest.json`, `project.toml`, `tasks/`, …). Importing then needs only the clone URL plus the branch.
  - **No force:** each export is a child of the branch tip and the ref update checks the old tip, so nothing is forced. Re-exporting unchanged content makes no commit.
  - **Push:** it pushes only that branch, `push -u origin`, never `--force`. A diverged remote is refused, and the local commit is kept.
  - **Result:** it reports branch, commit, committed and pushed.
- **Server:**
  - **Export route:** `mode: "branch"` needs `confirm: true`, like the git mode.
  - **Import route:** `source_branch` is passed to `clone_for_import(url, into, branch)`, so importing from the export branch works.
- **Browse button:** a new `POST /api/pick` endpoint opens the native folder dialog (pywebview `create_file_dialog`) through the window the app creates. In a browser it returns `available: false`, and the dialog tells the user to type the path.
- **Dialog fields:** the Browse button sits next to the config-repo, import-source and import-repo fields, which stay editable. The `.zip` upload keeps its normal file input.
- **Placeholders:** the import ones had real tab and newline characters in them. They now read `D:/work/my-repo` and similar.
- **Layout:**
  - **Export mode selector:** Zip file, GitHub branch, or Git folder. The choice sets the button text, a hint line and which fields show.
  - **Layout:** the fields are grouped under headings, with the input and Browse on one row. A status box wraps long text, and the buttons sit in a right-aligned footer row.
  - **Sizing:** the dialog is `min(560px, 94vw)` wide, scrolls if too tall, and uses the existing theme variables for light and dark.
- **Tests:** two new tests in `tests/test_export_import.py`.
  - **Local branch:** checks that branch, HEAD, status and uncommitted files are unchanged, that a repeat export makes no commit, and that a change makes a child commit.
  - **Push and import:** checks the push, a diverged remote being refused, and the clone-by-branch import.

NOTES:
- Branch export puts files at the branch root and never touches the checkout. The clone-by-branch import goes through `clone_for_import(..., branch=)`.
- `/api/pick` only works in the pywebview window, via the module global `server._WINDOW`; in a browser it returns `available: false`.
- Two tests (diverged remote, import from the branch) run the real git push and clone against a local bare repo.

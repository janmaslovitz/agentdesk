The repo has no `build_exe.ps1` in the revision I worked from. The built-in Build and Clean+rebuild buttons fail with a clear log message there; only the `[build] command` path was exercised.

- **Core (`agentdesk/core.py`):**
  - Build and Clean+rebuild run `build_exe.ps1` from the build worktree. "Custom" runs `[build] command` from `project.toml`. The command never comes from request text; a test posts a bogus `command` field and it is ignored.
  - The build runs in a separate detached worktree at `<project>/build/src`. The source is a branch or commit and defaults to the base branch. Build reuses that worktree for incremental builds. Clean+rebuild deletes it and recreates it.
  - The process runs with no console window. Output streams to `<project>/build/build.log`, and status goes to `status.json`.
  - Only one build runs at a time per project. Stop kills the whole process tree (`taskkill /F /T` on Windows). The result path defaults to `dist/AgentDesk/AgentDesk.exe` and can be changed with `[build] result`.
- **Server (`agentdesk/server.py`):**
  - Routes: `GET /api/p/<p>/build` (status, duration, result path and a log tail), `POST .../build`, `POST .../build/stop` and `POST .../build/open`.
  - Start and stop need `confirm:true`. Start is refused while `runner(p).running()` is true.
- **UI (`agentdesk/web/index.html`):**
  - The panel has a branch/commit box, Build, Clean + rebuild, Custom build (shown only when a command is configured), Stop and Open folder.
  - It loads on project switch and after its own actions. It re-reads every second only while a build is running, not on the main poll.
- **Tests (`tests/test_build_panel.py`):** a fake build command covers start, status, log, failure, one-at-a-time, clean, the HTTP routes and the task-run refusal. The Stop test starts a grandchild process and checks it is gone, as a stand-in for PyInstaller dying with PowerShell.

NOTES:
- Build state lives in `<project>/build/` (`src/` worktree, `build.log`, `status.json`). The status values are idle, running, ok, failed and stopped.
- Build routes are under `/api/p/<p>/build[/stop|/open]`. Start and stop need `confirm:true`; `open` does not.

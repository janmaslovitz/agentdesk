## Worker summary

All three changes are in and `pytest tests` passes (245 tests, 2 of them new; the suite already had 243, not 174).

- **Router skip:** `route()` in `core.py` now returns `{"tier", "why": "set in the task file", "brief": task.body}` straight away when `task.tier` is set, without calling `query()`. It still writes the `routed` activity event. I removed the old tier override at the end of `route()` because it can no longer be reached. `plan_tasks()` needed no change.
- **`load_tasks` cache:**
  - **Keying:** `core.py` caches each file keyed by path, with `(mtime_ns, size)` and either the parsed task or a skip marker for draft/invalid files.
  - **Invalidation:** entries for deleted files are dropped, and a lock guards the cache because the server calls `load_tasks` from threads.
  - **Returned tasks:** callers get copies, so changing `crates` or `depends` on a returned task doesn't touch the cache.
- **Lazy SDK import:**
  - **Names and patching:** `core.py` and `server.py` no longer import `claude_agent_sdk` at the top. A `_load_sdk()` in each file imports it on first use and puts the names into the module globals. A module-level `__getattr__` loads it for lookups like `core.query`, `monkeypatch.setattr(core, "ClaudeSDKClient", …)` and `server.ClaudeSDKClient`, so the existing patching tests keep working.
  - **Where it loads:** `_load_sdk()` is called at the SDK entry points: `guard`, `options`, `route`, `work`, `Chat.__init__`, `memory_call` and `live_agents`. `main()` also starts a background thread that preloads the SDK, so the first chat doesn't pay the import.
  - **Console hiding:** the Windows console-hiding patch now runs when the SDK loads, not at import.
  - **Spec file:** `agentdesk.spec` is unchanged.

Cold start, `import agentdesk.__main__, agentdesk.server`, three runs each: before 0.74–1.08s, after about 0.15s. I timed the import chain, not the full app launch to the window.

The second checks that an edit, an add and a delete each show up, and that changing a returned task doesn't affect the next call. I edited both Python files with the original CRLF line endings kept.

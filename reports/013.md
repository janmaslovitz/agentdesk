# 013: Chat opens an empty console window (claude CLI) on Windows

Branch `auto/013` at 6112299; tiers standard.

## Brief

Goal: on Windows, sending a message in the Assistant or Coworker chat must not open an empty Claude CLI console window. The chat should still talk to the CLI in the background, the way the workers do.

Likely cause (verify first): the chat creates `ClaudeSDKClient` (agentdesk/server.py:400-408, `Chat._client`, with `_assistant_options` at :374 and `_coworker_options` at :384). The SDK starts claude.exe via anyio.open_process with no creationflags (claude_agent_sdk/_internal/transport/subprocess_cli.py, ~line 873; it's in site-packages, not this repo). Runner.start (server.py:64) already uses CREATE_NO_WINDOW, which is why runs are fine. Also check the one-shot ClaudeSDKClient at agentdesk/core.py:772 for the same problem. requirements.txt pins claude-agent-sdk>=0.2.166. Before choosing a fix, check how that version exposes the subprocess (transport option or subclass hook). Options: a small Windows-only helper in core.py that wraps the transport or anyio.open_process, limited to the SDK, or a supported option if one exists.

Constraints:
- Windows only. No behaviour change on macOS/Linux.
- Don't change permission checks, approval cards, or the guard (Chat.permission, coworker_permission, coworker_hook).
- Don't change Runner.start or the run arguments (server.run_args).
- Don't add Bash or PowerShell to allowed_tools.
- Tests: from the repo root, `PYTHONDONTWRITEBYTECODE=1 python -m pytest -q -p no:cacheprovider tests`. Never touch the real data/ directory (tests use a temp AGENTDESK_HOME via conftest.py). __pycache__ is tracked in git, so don't leave .pyc changes behind.

Done when:
1. Start AgentDesk with no console (AgentDesk.cmd or pythonw). Send an Assistant message: no new console window appears and the answer comes back.
2. Same in Coworker mode, with a message that runs a shell command.
3. Verify during the message with the process list (e.g. Get-Process/CIM for claude.exe with a console) and a window list check. Report which method you used.
4. Tests pass. Report what was tested and whether the cause was confirmed or something else turned up.

## Worker summary

On Windows, the SDK now starts the Claude CLI with `CREATE_NO_WINDOW`, which is what should stop the empty window. I did not run the end-to-end check in a real no-console AgentDesk session. Criteria 1–3 (a message in Assistant and Coworker mode, with a process and window list check) are untested, so no process or window-list method was used.

**What I found.** The cause matches the brief:
- The SDK (0.2.166, `subprocess_cli.py:873`) calls `anyio.open_process` with no `creationflags`, so each CLI child gets its own console when the dashboard runs under `pythonw`.
- It does the same for the version check (`claude -v`, line 1171).
- The `transport=` option exists on `ClaudeSDKClient`, but a custom transport bypasses the SDK's own option and flag handling, so I didn't use it.
- `Runner.start` already used `CREATE_NO_WINDOW`; the chat path never did.

**What I changed.** In `agentdesk/core.py`, I added `_hide_sdk_console()` and call it at import.
- On Windows only, it replaces the `anyio` name inside the SDK's `subprocess_cli` module with a small proxy. The proxy's `open_process` adds `CREATE_NO_WINDOW` and passes everything else through to anyio.
- Nothing global is patched, and macOS/Linux are unchanged.
- Because `server.py` imports `core`, this covers both the chat clients (`Chat._client`, Assistant and Coworker) and the one-shot client at `core.py:772`.
- I didn't touch permissions, the guard, `Runner.start`, the run arguments, or `allowed_tools`.

**What I tested.** The full suite passes: 81 tests. A direct call to the patched `open_process` ran a child and returned its output. I did not add a new test.

NOTES:
- The SDK spawns the CLI via `subprocess_cli.anyio.open_process`. `core._hide_sdk_console()` adds `CREATE_NO_WINDOW` on Windows by swapping that module's `anyio` name for a proxy.
- Avoid the `ClaudeSDKClient(transport=...)` option: it skips the SDK's option and flag handling.
- The end-to-end no-window check in a real pythonw session is still outstanding.

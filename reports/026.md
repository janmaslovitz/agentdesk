## Brief

Goal: let a project give its workers optional extra MCP servers from project.toml `[mcp.<name>]` (first use: code-graph-mcp for Sintec.PDF). Do not edit any project's own project.toml.

- `options(p, **kw)` ~L2065: currently just builds ClaudeAgentOptions. Add role-aware mcp_servers injection here (or a helper it calls), passing `{name: {"type":"stdio","command":...,"args":[...],"env":{...}}}`. Merge with any mcp_servers already in kw. - `work()` ~L2221: worker options, `can_use_tool=guard(wt)` at ~L2228. Verify guard (~L1998) does not deny mcp__ tools (it currently only checks shell commands and edit tools, so it should allow them; confirm and add a test or explicit comment).

- Cwd: the server's cwd must be the worktree `wt`, so it must be set per-worker, not from the project config. Pass cwd through the stdio config if the SDK supports it, otherwise document it.

Constraints: invalid or missing config must never break a run; log one line via store.log and skip that server. Config keys absent = behaviour unchanged. Do not add network calls in tests. Don't touch the SDK lazy-loading rule: call `_load_sdk()` before using SDK names in new code.

Docs: short "MCP servers" section in README.md and an entry in CHANGELOG.md (both at repo root).

Tests: add tests for config → options conversion (roles, enabled flag, invalid entries skipped, Windows npx resolution via monkeypatched shutil.which, router excluded by default, allowed_tools untouched unless listed). Also a test that guard allows an mcp__ tool name.

## Worker summary

Projects can now give workers extra MCP servers from `[mcp.<name>]` in `project.toml`, and `pytest tests` passes (302 tests). I didn't run an end-to-end task with a real MCP server. I did not touch any project's own `project.toml`.

- **Config parsing:** a new `Project.mcp(log)` returns only valid, enabled entries. It checks `command`, `args`, `env`, `enabled` (default false) and `roles` (default `["worker"]`). Each bad entry is skipped with one `store.log` line.
- **Options:** `options()` takes `role=` and `log=`. It adds `{type: "stdio", command, args, env}` for servers whose roles include that role, merged with any `mcp_servers` already passed. `route()` passes `role="router"` and `work()` passes `role="worker"`. `allowed_tools` is never widened.
- **npx on Windows:** the command goes through `shutil.which`, so `npx` becomes `npx.cmd`. If `which` finds nothing, the command is left as written.
- **Working directory:** the SDK's stdio config has no `cwd` field. The server starts in the CLI's working directory, which is the worktree because `options(cwd=wt)` sets it. This is noted in the code and the README.
- **Guard:** I confirmed `guard()` already allows `mcp__*` tools, and added a comment and a test.
- **`.code-graph/`:** `commit()` now runs `git add -A -- . ":(exclude).code-graph"` and then removes any `.code-graph` entries from the index. This doesn't rely on `.git/info/exclude`. A test commits a worktree containing `.code-graph/index.db` and confirms only `a.txt` is tracked.
- **Docs and tests:** I added an "MCP servers" section to the README and a CHANGELOG entry. The tests are in the new `tests/test_mcp.py`.

NOTES:
- SDK `McpStdioServerConfig` has no cwd; the server inherits `options(cwd=...)`, so the worktree is the cwd for workers.
- Pass `role="worker"` or `role="router"` to `core.options()` for MCP injection; callers that omit `role` get no MCP servers.

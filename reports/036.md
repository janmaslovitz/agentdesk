## Brief

Part 4 of the AgentDesk Server. Needs tasks 1-3.
- Console admin tool `agentdesk-server` (python -m agentdesk server ...): `init` (creates server-home, server.toml with sensible defaults, first admin interactively or via --admin-password-file), `user add|list|passwd|disable|delete`, `status`, `config get|set` (host, port, tls, idle timeout, run_as_users), `doctor` (checks git, claude CLI present and logged in, ports, permissions, disk). All usable over SSH with no browser.

Dependencies listed: python3 (>=3.10), git, nodejs/npm note for the claude CLI. Do not require pywebview/pystray on the server.
- GitHub Actions: add a job to .github/workflows/release.yml that builds the .deb on ubuntu and attaches it to the release (look at how the existing mac/linux jobs attach files; keep the previously fixed attach step behaviour).
- Docs: README section "Server (Debian, headless)": install, init, first login, adding users/projects, updating, backup of /var/lib/agentdesk-server, security notes (LAN only, put TLS in front, no public internet exposure), troubleshooting. CHANGELOG under Unreleased.
Tests for the CLI commands (user add/list/passwd on a temp server-home) and for the packaging script's file layout if feasible without dpkg. Do NOT bump the version or tag.

## Worker summary

The console admin tool, the Debian package build, the release job and the docs are in. All tests I ran pass. A full-suite run was still going when I stopped, so I have no final result for it. What I did run: the new tests, the release-CI, gateway, admin, serve, version and datahome tests. I couldn't build or install the `.deb` here (no `dpkg-deb`), so the package itself is untested. The tests cover its file layout and run `sh -n` on its scripts.

- **Console tool:** `agentdesk-server` / `python -m agentdesk server` has `init`, `user add|list|passwd|disable|enable|delete [--purge]`, `status`, `config get|set` and `doctor`, as specified. It reads passwords from a file or prompts for them, never from arguments.
- **Config location:** `config.py` now honours `AGENTDESK_SERVER_CONFIG`, so `server.toml` can sit in `/etc/agentdesk-server` while state stays in `/var/lib/agentdesk-server`. `config set` edits `server.toml` in place and restores the old file if the new value fails validation.
- **Script rename:** the existing `agentdesk-server` script in `pyproject.toml` pointed at the headless `serve` command. That command is now `agentdesk-serve`, and the docs say so.
- **Debian package:** `packaging/debian/build_deb.py` builds `agentdesk-server_<ver>_all.deb`.
  - **Install:** the postinst creates a venv in `/opt/agentdesk-server`, with the app on it via a `.pth` file. It installs `claude-agent-sdk` only (no pywebview or pystray), from bundled wheels if you pass `--bundle-wheels`, otherwise from PyPI.
  - **Service:** it creates the `agentdesk` system user and a hardened `agentdesk-server.service` (`Restart=on-failure`, `NoNewPrivileges`, `ProtectSystem=full`, `ProtectHome`, `PrivateTmp`). Logs go to journald.
  - **Extras:** the `/usr/bin/agentdesk-server` wrapper, nginx and Caddy examples, and a firewall note for the LAN.
- **CI:** a new `deb` job in `release.yml` builds the package and uploads it with `--clobber`, same as the build job. The `publish` job now waits for both `build` and `deb`. I updated the existing release-workflow test to expect that.
- **Docs:** the README has the "Server (Debian, headless)" section and the CHANGELOG has entries under Unreleased. I did not bump the version or tag.
- **Tests:** `tests/test_server_admin.py` covers the CLI commands on a temp server-home, the package layout, and the workflow.

One thing differs from the brief: the package depends on Python 3.11 or newer, not 3.10, because the code uses `tomllib`.

NOTES:
- `AGENTDESK_SERVER_CONFIG` overrides the `server.toml` path. The gateway service is `python -m agentdesk gateway`, the headless instance command is `agentdesk-serve`, and the admin tool is `agentdesk-server`.
- `run_as_users` (sudo) conflicts with the unit's `NoNewPrivileges=true`; it needs a systemd drop-in with `NoNewPrivileges=false`.
- The `.deb` is built with `python3 packaging/debian/build_deb.py`; use `--stage-only DIR` to build just the file tree without `dpkg-deb`.

## Brief

Goal: the installed app can update itself with one button.
Today: no updater exists. Version is agentdesk/__version__ (core.py ~line 250 exposes it via a version-info dict). Installers are built by release.ps1/build_installer.ps1 as AgentDesk-Setup-x.y.z.exe. Repo: janmaslovitz/agentdesk (public).
Do:
1. core.py: check_update() -> GET https://api.github.com/repos/janmaslovitz/agentdesk/releases/latest (urllib, short timeout, no auth, User-Agent set); compare the tag (vX.Y.Z) with __version__ as numeric tuples; pick the asset named AgentDesk-Setup*.exe. Cache result ~1h; never block startup, never raise (offline = "unknown").

3. server.py endpoints: GET /api/update (current, latest, available, notes) and POST /api/update/install (download in background with progress, then launch the installer detached, e.g. with silent flags if the installer supports them - check installer/ - and exit the app so files can be replaced). Refuse while a worker run is active unless confirmed. Only when core.FROZEN (installed build); in dev mode just report.
4. UI (agentdesk/web): small "Update available v X" badge/button in the header, with progress and an error message; checks once at start in the background (setting in settings.toml to disable).
5. Tests for version comparison, asset selection, URL allow-list, and that failures are swallowed. Run `pytest tests`. Add a CHANGELOG "Unreleased" entry. Do NOT run release.ps1 or push.
Done when: tests pass and with a mocked release response the button appears and triggers the install flow.

## Worker summary

The installed app now has an "Update available vX" button that downloads the new installer from GitHub Releases and runs it. `pytest tests` passes (347 tests). The install flow is only tested with a mocked release and a stubbed installer launch. I haven't clicked the button in a real browser or run a real installer.

- **`core.py`:**
  - `check_update()` fetches the latest release, compares the tag to `__version__` as numeric tuples, and picks the `AgentDesk-Setup*.exe` asset. It caches for 1 hour, and any failure comes back as status "unknown" instead of an error.
  - `download_update()` streams the installer to a fresh temp dir and checks the size. It also checks the sha256 when the release has a `.sha256` asset or a digest. Download addresses, including redirects, must be https on github.com or the githubusercontent hosts.
  - A new `[updates] check = true` section in the default `settings.toml` lets you turn the check off.
- **`server.py`:**
  - `GET /api/update` returns current, latest, available and notes, plus the download progress.
  - `POST /api/update/install` refuses outside the installed Windows build and while a worker run is active unless `confirm` is true. Otherwise it downloads in the background, starts the installer detached with `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`, and shuts the app down.
  - The installer's "Start AgentDesk" step is skipped in silent mode, so the detached command relaunches `AgentDesk.exe` after the install.
- **UI:** I put the badge in the sidebar next to the version line rather than a header. The per-project top bar is redrawn per project, so it wasn't a stable place for it. It shows a progress percentage, an error message, and a confirm prompt when a run is active. It checks once when the page loads; the request runs in the background and doesn't delay startup.
- **Tests and changelog:** `tests/test_updater.py` covers version comparison, asset selection, the URL allow-list, swallowed failures plus caching, checksum and size checks, and the install flow. `CHANGELOG.md` has an Unreleased entry.

NOTES:
- Installer launch uses `cmd /c "<setup>.exe /VERYSILENT … & start AgentDesk.exe"`. `AgentDesk.iss` has no silent-mode relaunch of its own.
- The updater needs the release to have an `AgentDesk-Setup*.exe` asset; adding a `.sha256` asset enables checksum verification.
- `server.py` defines `QUIT` twice. The later one (near `start_tray`) is the one `main()` watches.

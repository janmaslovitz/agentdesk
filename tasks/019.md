GOAL
The dashboard manages each project's task queue by itself, with plain code (no model calls, no tokens). It is an app-wide feature: every project, including every NEW project, gets it automatically with the defaults below. No per-project setup is needed; a project may override or turn it off.

BEHAVIOUR (a background loop in the dashboard server, one pass every ~30 s while the dashboard runs)
1. Start next: if the project has no run going and has a pending task whose dependencies are all done, start it (the same path as run_next). One run per project at a time, as today.
2. Stale state recovery: a task marked `working` whose run process no longer exists (check the runner pid / project runner.pid) is set back to a recoverable state (`pending` with `last_failure` noting "worker exited unexpectedly (code N)" when known). Example today: exit code 129 left 008 stuck as `working`.
3. One automatic retry: if a run ended by crash/kill/infrastructure error (not a failed gate or a task-level failure), retry the task once; after that, stop and flag it.
4. Respect limits: do nothing while the account usage gate (task 007) says paused; never start a run when the project is blocked by a pending approval.
5. Flag for review (needs a human or the Coworker): failed gates, repeated failures, merge conflicts, a done task whose branch is not yet merged (task 015) and has not been reviewed. Flags appear as a "Needs attention" list in the dashboard (count badge + list with reason, task id, a button to open the report/log) and are written to the project's log. No action is taken on flagged items automatically.
6. Never merge, push, delete branches or change remotes automatically. Starting queued tasks and retrying once are the only automatic actions.

SETTINGS
- App-wide defaults in settings.toml: `[autorunner] enabled = true, interval_s = 30, retry_crashed = 1`.
- Per-project override in the project's config: `[autorunner] enabled = false` etc. New projects (add_project) simply inherit the defaults; do not write per-project values unless the user changes them.
- A dashboard toggle per project (on/off) and a global one; the state is visible (e.g. "Auto: on / paused: usage limit / waiting: needs attention").
- An existing project with no override is treated as enabled after the update.

WHERE
- agentdesk/core.py: pure functions (next_startable, recover_stale, classify_failure, attention_items) so they are testable without a server.
- agentdesk/server.py: the loop thread started in main(), API `GET /api/attention`, `POST /api/projects/<p>/autorunner`.
- agentdesk/web/index.html: toggle, status, Needs attention list.
- tests/: unit tests for the pure functions with fake state; a test that a freshly added project is auto-managed with defaults.

CONSTRAINTS
- No model/API calls from the loop. Cheap: only reads state.json and checks pids.
- Only one dashboard instance runs the loop (use the existing single-instance logic); no double-starts after restart.
- Work only in an isolated clone with a temp AGENTDESK_HOME; never the live checkout or its data/. Use a non-default port (e.g. 8799) for dashboard tests.
- Do not start real worker runs in tests; fake the run starter.

DONE WHEN
- With two projects and a queue, tasks start one after another without any click; a killed run is recovered and retried once, then flagged.
- A project created after this change is managed with no extra setup (tested).
- Gate failures and unmerged done branches show under Needs attention; nothing is merged or pushed automatically.
- python -m pytest tests passes; report what was actually tested.

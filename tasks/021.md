Two bugs in the chat panel of the dashboard (agentdesk/web/index.html, server in agentdesk/server.py).

1. Mode switch: the "Coworker" button overlaps/blocks the "Planner" button in the Chat header. The mode segment is `<span class="seg" id="modeSeg">` inside the Chat `<h3>` (line ~331), together with the `coworkBadge`, `chatModel` and a spacer and "New chat". Make all three mode buttons (Assistant, Coworker, Planner) fully visible and clickable at the default window width, and let the header wrap or shrink the badge/model text instead of covering the buttons. Check the `.seg` and `h3` CSS rules.

2. Idle chat shows "working…" and the Stop button does nothing. The live bar (`#liveBar`, `showLive()`, ~line 580) is shown when `chat_live && chat_busy` from /state. On the server, `Chat.busy` (server.py ~lines 403-1140) can stay True after a turn ends, so the bar keeps spinning while the assistant is idle. `interrupt()` (~line 1024) returns early when `busy` is False, so Stop silently does nothing. Find where `busy` is set/cleared (the result handler, the error/timeout paths, the background-turn path around line 913, and the reset path) and make sure it is False when no turn is running. Also make Stop reliable: if the bar is shown, Stop must end the bar. Stop must always give feedback (a note in the chat) instead of silently doing nothing.

Constraints: do not change the mode names or the chat behaviour of Coworker/Planner beyond these fixes; keep the existing tests passing (run `pytest tests`, not the whole data folder).

Done when: (a) all three mode buttons are clickable in the header at normal width; (b) after a reply finishes, the "working…" bar disappears and /state reports chat_busy false; (c) pressing Stop during a real turn interrupts it and clears the bar; pressing Stop when idle does not show the bar and leaves a clear note; (d) tests added or updated for the busy flag reset, and the test suite passes.

Problem: Sintec.PDF's folder grew to ~600 GB (already cleaned by hand). Today still ~190 GB: target-agents 114 GB (debug/deps alone 109 GB: stale test binaries/rlibs of every past build hash), target-coworker 57 GB, target-017 19 GB (a leftover per-task target dir). Nothing watches this. Add disk hygiene to AgentDesk (agentdesk/core.py, server.py, web/index.html; a background job like the existing auto-runner/health polling).

1. Measure: per project, sizes of (a) every cargo target dir it uses — CARGO_TARGET_DIR from [gates.env], any `target*` sibling dirs next to the repo that match the pattern or were used by a task, and `<repo>/target`; (b) the worktrees dir; (c) the project's AgentDesk data dir (logs, runs/*.jsonl, reports). Walk off the event loop, with os.scandir (fast, no stat storms), cache the result for a few minutes, never block a dashboard request; show the numbers in the dashboard (a compact 'Disk' line/section per project with breakdown and a 'Clean up' button) and a warning when over a threshold.
2. Config in project.toml: [hygiene] enabled = true, max_target_gb = 60 (per target dir), max_total_gb = 150, stale_days = 3, auto = false by default (suggest only) — plus app-wide defaults in settings.toml. Validate; invalid config never crashes.
3. Cleaning actions (each reports bytes freed and is logged to agentdesk.log): 
   - target dir over limit: first cargo-sweep-style trim — delete files in debug/deps, debug/build, debug/.fingerprint, debug/incremental older than stale_days (by mtime); if still over max_target_gb, remove the whole `debug` (or `release`) profile dir of that target, which is only a build cache. Never touch non-target dirs, never follow symlinks/junctions out of the dir (check reparse points on Windows), refuse paths that are not clearly a target dir (must contain CACHEDIR.TAG or .rustc_info.json or be named target*), and refuse anything outside the project's configured locations.
   - orphan per-task target dirs (e.g. target-017) with no live task/worktree and older than stale_days: remove.
   - worktrees of tasks that are done and merged (or whose branch is gone): `git worktree remove --force` + prune; merged auto/* branches may be deleted only when merged into the base.
   - trim old runs/*.jsonl and logs beyond a size cap (keep reports and state.json untouched).
4. Safety: do nothing while a run is active for that project, or while any cargo/rustc/rustup process has a command line or cwd inside the dir (check via psutil if available or `wmic`/PowerShell Get-CimInstance on Windows; if the check fails, skip). Default to dry-run: the UI shows what would be deleted and how many GB, and deletes only on the user's click, unless auto = true. Windows: deletion must handle read-only files and long paths (use `\\?\` prefix or rmtree with onerror chmod); never prompt; windowless subprocesses as elsewhere.
5. Also check the project's gate env for avoidable bloat and just report it in the Disk section: e.g. CARGO_INCREMENTAL not 0, debug info not disabled, one shared target for many differing worktrees (cache churn). Do not edit project.toml automatically.
6. Tests (no real huge dirs; tmp_path fixtures): size walker, stale trimming by mtime, refusal of non-target paths and of paths outside the project, skip while a process uses the dir (mock), dry-run vs apply, config validation. `pytest tests` (not bare pytest) must pass. Report how to try by hand.

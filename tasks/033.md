Part 1 of the AgentDesk Server (Debian, headless, LAN). Overall design: a gateway process authenticates users and reverse-proxies each user to their OWN AgentDesk instance (separate process, own AGENTDESK_HOME data folder); an admin cabinet manages users/projects. Agents/workers run server-side. This task is only the foundation.

Do: add `python -m agentdesk serve` (also entry point `agentdesk-server`) that runs the dashboard server with NO pywebview/pystray/browser import at all (must work on Linux without a display and without those packages; lazy-import them elsewhere if needed), configurable `--host` (default 127.0.0.1), `--port`, `--data` (sets AGENTDESK_HOME before core is imported, see core._data_home), logs to stdout/journald, clean shutdown on SIGTERM/SIGINT, pid file optional. Server.py currently hardcodes 127.0.0.1 (main(), answers(), the Handler's origin/host checks and any DNS-rebinding / CSRF protections): make the allowed Host/Origin configurable (`--allowed-host`, defaults derived from host/port) so the UI works when opened as http://192.168.x.x:8765 but still rejects foreign origins. SAFETY: refuse to bind a non-loopback address unless `--trust-proxy-auth` / a flag `--auth-token-file` is given (a shared secret every request must carry as header X-AgentDesk-Gateway-Token, compared in constant time); that is how the gateway (task 2) will talk to instances. Without the flag, binding to 0.0.0.0 must fail with a clear message.
Also: Linux paths in core (git, claude CLI lookup, no Windows-only calls like creationflags/CREATE_NO_WINDOW, no LOCALAPPDATA assumption) - audit and fix so the whole core runs on Debian; check subprocess usage in core.py and server.py. Tests: pytest tests (not bare pytest); add tests for the host/origin rules, the token check, the refusal to bind publicly. CHANGELOG under Unreleased. Done = tests pass and `python -m agentdesk serve --port 0`-style start works in a test.

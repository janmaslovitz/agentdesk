Part 2 of the AgentDesk Server. Needs task 1 (`agentdesk serve` with --host/--port/--data and the gateway-token header).

Build `agentdesk/gateway/` (new package, stdlib only if possible; threaded HTTP server like server.py) started by `python -m agentdesk gateway` (listens on a LAN address, default 0.0.0.0:8080 configurable in `<server-home>/server.toml`):
- User store `<server-home>/users.json` (atomic durable writes like core.write_json): username, role (admin|user), password hash (hashlib.scrypt with per-user salt, constant-time compare), disabled flag, created time, `home` (the user's data folder `<server-home>/users/<username>/`), assigned project slugs/accounts. Never log or return hashes.
- Login page (plain HTML, no external assets) at /login, POST sets a random session cookie (HttpOnly, SameSite=Strict, Secure when TLS), server-side session table with expiry, logout, brute-force throttle per user+IP, CSRF protection for state-changing calls (token or Origin check).
- After login: proxy EVERYTHING else (/, /api/*, static, chat polling, uploads/downloads incl. export zip, streaming responses) to that user's own instance. Instances: the gateway starts `python -m agentdesk serve --host 127.0.0.1 --port <free port> --data <user home> --auth-token-file <secret>` lazily per user, supervises/restarts them, stops idle ones after a configurable time (runs in progress must keep the instance alive), and sends the shared token header. Instance ports bind to loopback only. Users must never reach another user's instance or data: enforce by session->instance mapping only, never by a client-supplied id.
- Optional OS isolation: if `run_as_users = true` in server.toml, start the instance via `sudo -n -u agentdesk-<username>` / systemd-run (document, don't require).
- Optional TLS (`tls_cert`, `tls_key` in server.toml) for the gateway listener.
- Audit log of logins/failed logins/user changes (`<server-home>/audit.log`).
Tests (pytest tests): password hashing, login/logout/session expiry, throttle, isolation (user A cannot read user B's data through the proxy), proxy passes through POST bodies/binary, instance lifecycle with a fake instance. CHANGELOG under Unreleased. Keep dependencies out of requirements unless unavoidable.

Part 4 of the AgentDesk Server. Needs tasks 1-3.
- Console admin tool `agentdesk-server` (python -m agentdesk server ...): `init` (creates server-home, server.toml with sensible defaults, first admin interactively or via --admin-password-file), `user add|list|passwd|disable|delete`, `status`, `config get|set` (host, port, tls, idle timeout, run_as_users), `doctor` (checks git, claude CLI present and logged in, ports, permissions, disk). All usable over SSH with no browser.
- Debian packaging: a `packaging/debian/` build script producing `agentdesk-server_<ver>_all.deb` (or amd64 with a bundled venv, pick the simplest that works offline-ish: dpkg-deb with a venv in /opt/agentdesk-server created in postinst from bundled wheels or pip), dedicated system user `agentdesk`, state in /var/lib/agentdesk-server, config /etc/agentdesk-server/server.toml, logs via journald, systemd unit `agentdesk-server.service` (Restart=on-failure, hardening: NoNewPrivileges, ProtectSystem, PrivateTmp where compatible with spawning git/claude), example nginx/Caddy TLS reverse proxy snippet, firewall note for LAN. Dependencies listed: python3 (>=3.10), git, nodejs/npm note for the claude CLI. Do not require pywebview/pystray on the server.
- GitHub Actions: add a job to .github/workflows/release.yml that builds the .deb on ubuntu and attaches it to the release (look at how the existing mac/linux jobs attach files; keep the previously fixed attach step behaviour).
- Docs: README section "Server (Debian, headless)": install, init, first login, adding users/projects, updating, backup of /var/lib/agentdesk-server, security notes (LAN only, put TLS in front, no public internet exposure), troubleshooting. CHANGELOG under Unreleased.
Tests for the CLI commands (user add/list/passwd on a temp server-home) and for the packaging script's file layout if feasible without dpkg. Do NOT bump the version or tag.


ADDITIONAL REQUIREMENT - Claude subscription login on a headless server (AgentDesk works on a Claude SUBSCRIPTION, not API keys):
- `agentdesk-server account add <name> --login`: creates the account folder (`<server-home>/claude/<name>`, 0700), registers it in the server settings with `config_dir`, and runs `claude` with `CLAUDE_CONFIG_DIR` set to it, interactively (inherit the TTY), so the operator signs in over SSH via the printed URL + pasted code. `account login <name>` repeats the login; `account list` shows signed-in or not; `account remove`.
- Optional: an account may instead use a long-lived subscription token from `claude setup-token` read from `CLAUDE_CODE_OAUTH_TOKEN` in a root-only EnvironmentFile (document it, never store it in users.json, never print it).
- `doctor` checks each account is signed in (reuse core's existing auth/usage check) and reports which accounts are shared by several users (they share the subscription limits).
- The admin cabinet's account page shows sign-in status and the SSH instructions (exact commands) instead of a login button; secrets are never displayed.
- README / docs/SERVER.md: a section "Signing in to Claude on a server without GUI" with both methods, the shared-limits note, and the reminder to check that the subscription terms allow the intended sharing. ALSO publish the whole Debian guide as docs/SERVER.md (and link it from README).

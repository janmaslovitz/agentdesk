Goal: rework the dashboard's Git window (web UI in agentdesk/web, API in agentdesk/server.py ~1838 and ~1916, logic in core.py git_remote/git_status/git_fetch/git_merge/git_pull/git_push ~1092-1200).

Today it only shows status and offers fetch/merge/pull/push for the project's current remote. Wanted:

1. Connect to a specific repository: show the current remote (origin URL) and let the user (a) pick one of the repositories visible to the chosen GitHub account (`gh repo list <owner> --json nameWithOwner,url,isPrivate --limit 100`) or (b) paste a URL/owner/name. Applying sets/changes `origin` (`git remote set-url` / add), with a confirmation, never silently; show errors verbatim.
2. Choose the account: list accounts known to the `gh` CLI (`gh auth status` / `gh auth status --json hosts` or parse; there may be several, e.g. sintec-llc and janmaslovitz) with the active one marked; switching uses `gh auth switch -u <user>`. Push/pull/PR operations must run as the selected account (switch before the operation or pass GH_TOKEN from `gh auth token -u <user>` in the child env only — never log or return tokens, never write them to files/config). Remember the chosen account per project in project.toml (key like [git] account = "name") and show which account an operation used. If gh is missing or not logged in, show a clear message with the command to run, not a crash.
3. Push: keep push (current/selected branch, set upstream when missing), show result.
4. Pull requests: list open PRs of the connected repo (`gh pr list --json number,title,headRefName,baseRefName,author,url,state,isDraft`), create a PR from the current/selected branch to the base (title, body, draft checkbox; `gh pr create`), open PR URL, and show checks/status summary if cheap (`gh pr view --json statusCheckRollup`). Merging a PR is NOT required (leave out, or behind an explicit confirm if trivial).
5. Everything runs off the event loop / in background like the other git calls (the dashboard must not freeze; windowless subprocess as elsewhere), with timeouts. Cache gh lists briefly (a few seconds), refresh on demand.

Constraints: no tokens in logs/responses/state; destructive actions (changing remote, creating PR, pushing) need an explicit user click, no auto-actions; keep existing fetch/merge/pull behaviour working; the existing API routes stay compatible. Language of the UI follows the rest of the app. Add tests for the pure parts (parsing gh JSON output, account switching command construction, remote URL validation) with subprocess mocked. Run `pytest tests` (not bare pytest); all must pass. Describe in the report how to try it by hand.
